## 화면정의서 (Screen Specification)

**문서명:** AI 1차 채용면접 자동화 플랫폼 화면정의서  
**파일명:** `Final_Project_화면정의서_v0.5.md`  
**버전:** v0.5  
**최종 작성일:** 2026년 10월 29일  
**진행 상태:** 초안 (Draft) / 팀 검토 반영 및 문서 정합성 검토  
**작성:** AIIT (AI Interview Training)  
**기준 문서:** 통합 PRD v1.6 · TRD v1.5 · 서비스 플로우차트 08v · 시나리오 기획서

### 문서 개요

본 문서는 AI 기반 1차 채용면접 자동화 플랫폼의 사용자 및 관리자 화면 구성과 동작 방식을 정의한 문서입니다.

통합 PRD v1.6, TRD v1.5, 서비스 플로우차트 08v를 기반으로 기능 요구사항을 실제 화면 단위로 구체화하였으며, 화면별 와이어프레임, 구성 요소, 버튼 동작, 화면 전환 조건, API 연계 및 예외 처리 방식을 정리하였습니다.

v0.5에서는 기존 화면 설계를 유지하면서 **AI 합불 판정 검증 기준, STT 최종 실패 처리, 장애 복구, 동시 면접 상한 및 문서 간 우선순위**를 최신 기술 요구사항에 맞게 수정하였습니다.

또한 문서 간 정책이 충돌하는 경우 적용할 기준을 명확히 하고, 화면별 기술 구현 문제와 추가 API·데이터 필드 요구사항을 관리할 수 있도록 구성하였습니다.

이를 통해 프론트엔드와 백엔드 개발 과정에서 발생할 수 있는 기능 해석의 차이를 줄이고, 실제 구현 및 테스트 과정에서 공통으로 참고할 수 있는 화면 설계 기준을 마련하는 것을 목적으로 합니다.

### 주요 작성 내용

- **화면 구조 및 정보 설계(IA):** 사이트맵, 화면 ID, URL 라우트, 사용자별 접근 권한 및 상태별 라우트 가드
- **화면 전환 규칙:** 지원자·관리자별 화면 이동, 버튼 클릭, 자동 전환 조건 및 응시 상태별 처리
- **공통 UI 규칙:** 레이아웃, 디자인 토큰, 버튼, 상태 배지, 알림, 모달, 오류 및 빈 상태 처리
- **인증 화면:** 로그인, 회원가입, 비밀번호 재설정 및 관리자 초기 비밀번호 변경
- **지원자 화면:** 공고 탐색, 필수 동의, 이력서 제출·OCR, 환경 점검 및 면접 시작 안내
- **AI 면접 화면:** 질문 준비, 음성 질문·답변, 실시간 STT 자막, 녹화 및 연결 상태 관리
- **코딩테스트 화면:** 시험 안내, 코드 작성, 자동 저장, 서버 기준 타이머 및 최종 제출
- **응시 예외 처리:** 네트워크 장애, STT 실패, 화면 이탈, 동시 면접 상한 초과 및 접수 마감
- **마이페이지:** 지원 내역, 응시 상태, 면접 이어가기, 결과 확인 및 계정 관리
- **관리자 화면:** 공고 생성·수정, AI 공고 자동 생성, 지원자 관리·비교, 다음 전형 대상자 및 통계 대시보드
- **기술 구현 검토:** Next.js 라우팅, 전체 화면 유지, WebSocket 통신, 장애 감지 및 브라우저 제어
- **개발 연계 사항:** TRD 반영 대상 API·데이터 필드, 문서 간 충돌 사항 및 PRD 인수 기준 추적

### 버전별 주요 변경 사항

#### v0.3 — 화면 접근 및 UI 정책 보완

- 지원서 '작성 중' 상태와 화면 복귀 경로 보완
- 응시 상태별 URL 접근 및 라우트 가드 정의
- 모바일·태블릿 미지원 정책 및 안내 화면 추가
- 환경 점검 화면에 **[나중에 응시하기]** 버튼 추가
- 동시 면접 상한을 AI 면접에만 적용하도록 구분
- 코딩테스트 타이머 정지 및 재개 기준 구체화
- 화면 이탈 경고창 표시 중 재이탈 처리 규칙 추가
- 게시 중인 공고의 수정 가능 항목 및 변경 이력 표시 규칙 추가
- 빈 상태 UI와 브라우저 뒤로가기 제어 방안 정리

#### v0.4 — TRD v1.5 기술 요구사항 반영

**1. AI 판정 및 분석 상태 처리**

- AI 판정 결과와 합격 기준 간 불일치 시 '확인 필요'로 처리하는 규칙 추가
- AI 평가 및 판정 오류에 대한 관리자 재처리 경로 보완

※ 해당 AI 판정 검증 규칙은 v0.5에서 다시 변경되었습니다.

**2. 동시 면접 상한 및 응시 상태 정비**

- 동시 면접 상한 초과 시 별도의 '대기' 상태를 생성하지 않도록 변경
- 지원서 상태를 '준비 중'으로 유지
- 지원자가 직접 **[다시 시도]**하거나 마이페이지로 돌아가도록 구성
- 자동 대기열 및 대기 상태 배지 제거

**3. 화면 이탈 및 장애 처리 보완**

- 화면 이탈 1회차에는 답변 시간을 일시정지하고 남은 시간부터 재개
- 이탈 전후 음성을 하나의 답변으로 합쳐 처리
- 연결 장애 판단 시점을 Heartbeat 누락 후 15초로 명확화
- 장애 중단 시 동시 면접 자원을 최대 10분 유지
- 마이크·카메라 권한 직접 해제로 종료되는 경우의 별도 안내 오버레이(OV-07) 추가

**4. 실시간 면접 처리 개선**

- 답변의 실시간 STT 자막 표시 반영
- 꼬리질문 생성 판단 시간을 고정값이 아닌 남은 처리 시간에 따라 조정
- 서버 부하 및 처리 시간에 따라 꼬리질문을 생략할 수 있도록 구성

**5. 관리자 알림 정책 변경**

- 관리자 대상 '신규 지원' 알림 제거
- 운영상 필요한 알림과 분석 '확인 필요' 알림 중심으로 정리

#### v0.5 — AI 판정·STT 장애 처리 및 문서 우선순위 정비

**1. AI 합불 판정 검증 방식 변경 (D-06)**

- AI가 종합 점수, 합격 기준 및 평가 근거를 참고하여 1차 합격·불합격을 직접 결정
- 시스템은 AI 판정의 형식, 값 범위 및 근거 문장만 검증
- 시스템이 종합 점수와 합격 기준을 비교하여 AI 판정을 다시 결정하지 않도록 변경
- 판정 검증 실패 시 1회 재시도
- 재시도 이후에도 검증에 실패하면 '확인 필요' 상태로 전환
- 관리자는 **[재처리]** 기능을 통해 분석을 다시 요청

**2. STT 최종 실패 처리 방식 변경 (D-02)**

- STT 변환이 2회 재시도 이후에도 실패하면 시스템 장애로 분류
- 네트워크 연결이 정상이어도 '장애 중단' 상태로 처리
- 기존의 동일 화면 내 재답변 오버레이(OV-04) 삭제
- 장애 안내(OV-01) 이후 마이페이지로 이동
- 면접 이어가기 화면(S-A15)에서 환경을 재점검
- 재접속 후 중단된 질문을 처음부터 새로운 답변 시간으로 진행

**3. 기준 문서 및 우선순위 변경**

- 통합 PRD v1.6 반영
- TRD v1.5 기준 기술 처리 규칙 적용
- 서비스 플로우차트 08v 연계
- 2026년 10월 29일 팀 결정에 따른 문서 간 우선순위 명시

문서 간 우선순위는 다음과 같습니다.

**TRD → 화면정의서 → PRD → 시나리오 기획서 → 서비스 플로우차트**

문서 간 요구사항이나 처리 정책이 상충하는 경우, 해당 우선순위를 참고하되 팀 결정을 거쳐 변경 사항을 기록합니다.

**4. 화면 및 기술 연계 사항 정비**

- 삭제된 OV-04 관련 화면 전환 및 WebSocket `stt_retry` 요청 제거
- STT 실패 이후 장애 복구 경로와 응시 상태 매핑 일치
- AI 판정 결과 검증 관련 화면 문구 수정
- 기술 검토 항목과 TRD 반영 요청 목록 정리
- PRD 인수 기준과 화면별 기능 연결 관계 유지

### 주요 화면 설계 원칙

본 문서는 다음 원칙을 기준으로 화면을 설계하였습니다.

1. **명확한 사용자 동선:** 화면마다 다음 행동을 알 수 있는 주 버튼을 제공하고, 자동 전환 조건을 구분합니다.
2. **서버 기준 상태 관리:** 응시 상태, 마감 시각, 남은 시간 및 판정 결과는 서버 데이터를 기준으로 표시합니다.
3. **역할별 접근 제어:** 지원자와 관리자의 화면 및 API 접근 권한을 구분합니다.
4. **응시 화면의 연속성:** 면접과 코딩테스트는 동일 라우트 내에서 단계(phase)를 변경하여 불필요한 페이지 이동을 방지합니다.
5. **장애 복구 가능성:** 시스템 장애 발생 시 응시 상태를 보존하고 허용된 조건에서 이어가기를 지원합니다.
6. **일관된 예외 처리:** 오류, 연결 장애, 화면 이탈 및 접수 마감 상황에 대한 안내와 후속 동작을 정의합니다.
7. **기술 요구사항 연계:** 화면에서 필요한 API와 데이터 필드를 명시하고 TRD 반영 여부를 관리합니다.
8. **문서 간 추적성:** 화면 ID, 전환 ID, PRD 요구사항 및 기술 검토 항목을 연결하여 변경 영향을 확인합니다.

### 문서 활용 방향

본 화면정의서는 프로젝트의 **공통 UI/UX 설계 및 화면 구현 기준 문서**로 활용합니다.

PRD의 기능 요구사항과 서비스 플로우차트의 사용자 흐름을 실제 화면 구성으로 연결하며, 프론트엔드 개발과 백엔드 API 연동 과정에서 참고 자료로 사용합니다.

각 팀원은 공통 화면정의서를 기반으로 개별적인 프로그램 구현을 진행하되, 화면별 필수 기능과 응시 상태 처리, 접근 권한 및 예외 상황에 대한 요구사항을 확인하여 핵심 기능이 누락되지 않도록 합니다.

특히 v0.5에서 변경된 AI 판정 검증, STT 장애 처리, 응시 복구 및 화면 전환 규칙은 다른 공통 문서와의 정합성을 확인하고 실제 구현 환경에서 검증할 예정입니다.

### 향후 검토 사항

현재 v0.5는 초안 단계이며, 일부 화면 정책과 기술적 가정에 대한 추가 검토가 필요합니다.

- **결과 화면 문의 안내:** PRD에 문의 이메일 안내 허용 문구 반영
- **차별 표현 감지:** 규칙 기반 사전 방식에 대한 PRD·TRD 반영
- **로그인 복귀 경로:** TRD의 `next` 허용 경로와 실제 화면 라우트 간 불일치 수정
- **마감 중 녹음 처리:** 접수 마감 시 녹음 중이던 문항의 미응답 처리 기준 확정
- **화면 이탈 중 재이탈:** 경고창 표시 중 추가 이탈을 2회째 이탈로 처리하는 임시 규칙 검토
- **게시 후 공고 수정:** 수정 가능 항목과 변경 사항 표시 및 저장 구조의 PRD·TRD 반영
- **모바일 지원 정책:** PC 전용 운영 및 모바일 접근 제한을 PRD 비기능 요구사항에 명시
- **기술 구현 검증:** Next.js 뒤로가기 제어, 전체 화면 유지, WebRTC·WebSocket 연결 및 장애 복구 테스트
- **문서 정합성:** STT 장애 처리, AI 판정 및 기타 변경된 처리 기준을 PRD·플로우차트에 반영

검토 결과는 관련 PRD·TRD·화면정의서·서비스 플로우차트에 반영하여 문서 간 일관성을 유지할 예정입니다.

※ 본 문서는 **v0.5 초안 기준**이며, 실제 개발 및 테스트 과정에서 화면 구성, 기술적 구현 방식과 세부 동작 정책이 변경될 수 있습니다. 문서에 기록된 가정 및 미결 사항은 팀 검토를 통해 확정하고 이후 버전에 반영할 예정입니다.
