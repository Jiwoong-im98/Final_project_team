## 화면정의서 (Screen Specification)

**문서명:** AI 1차 채용면접 자동화 플랫폼 화면정의서  
**파일명:** `Final_Project_화면정의서_v0.6.md`  
**버전:** v0.6  
**최종 작성일:** 2026년 11월 3일  
**진행 상태:** 초안 (Draft) / 실제 구현 대조 반영 및 문서 정합성 검토  
**작성:** AIIT (AI Interview Training)  
**기준 문서:** 통합 PRD v1.6 · TRD v1.5 · 서비스 플로우차트 08v · 시나리오 기획서  
**대상:** 프론트엔드(Next.js App Router) · 백엔드(FastAPI) 개발자 · 디자이너

### 문서 개요

본 문서는 AI 기반 1차 채용면접 자동화 플랫폼의 사용자 및 관리자 화면 구성과 동작 방식을 정의한 문서입니다.

통합 PRD v1.6, TRD v1.5, 서비스 플로우차트 08v를 바탕으로 화면별 와이어프레임, 구성 요소, 버튼 동작, 화면 전환 조건, API 연계 및 예외 처리 방식을 구체화했습니다.

**v0.6에서는 2026년 11월 3일 기준 실제 구현(`huge/`)과 화면정의서를 대조**하여 화면 문구·버튼·라우트 등의 차이를 반영했습니다. 다만 PRD·TRD 등 다른 기준 문서와 충돌하는 구현 사항은 임의로 수정하지 않고, **§1.3의 H-01~H-10**에 별도 기록하여 팀 결정이 필요한 항목으로 남겼습니다.

### 주요 작성 내용

- **정보 구조 및 접근 제어:** 사이트맵, 화면 ID, URL 라우트, 역할별 권한, 응시 상태별 라우트 가드
- **화면 전환:** 지원자·관리자별 버튼 및 자동 전환 조건, 상태별 화면·버튼 매핑
- **공통 UI:** 레이아웃, 디자인 토큰, 알림·모달·오류·빈 상태, 모바일 미지원 안내
- **인증:** 로그인·회원가입·비밀번호 찾기 및 재설정·관리자 초기 비밀번호 변경
- **지원자 절차:** 공고 탐색, 필수 동의, 이력서 제출 방식 선택, OCR·이력서 확인, 환경 점검
- **면접·코딩테스트:** 질문 준비, 음성·실시간 STT, 응시 상태·녹화·연결 관리, 코딩 자동 저장 및 제출
- **응시 예외:** STT 최종 실패, 네트워크 장애, 화면 이탈, 동의 철회, 접수 마감, 동시 면접 상한 초과
- **마이페이지·결과:** 지원 내역, 결과 공개, 계정 관리, 장애 후 이어가기
- **관리자:** 공고 관리·AI 초안 생성·작성·미리보기, 지원자 목록·상세·비교, 다음 전형, 대시보드·설정
- **기술 및 추적성:** 예상 구현 문제, TRD 반영 필요 API·필드, 미결 사항, PRD 인수 기준(AC) 연결

### 버전별 주요 변경 사항

#### v0.3 — 화면 접근 및 UI 정책 보완

지원서 '작성 중' 상태, 응시 상태별 라우트 가드, 모바일·태블릿 미지원, **[나중에 응시하기]**, 화면 이탈·코딩 타이머·게시 후 공고 수정 규칙 등을 보완했습니다.

#### v0.4 — TRD v1.5 기술 요구사항 반영

동시 면접 상한 초과 시 별도 '대기' 상태를 만들지 않고 '준비 중'으로 유지하도록 정비했습니다. 이탈 1회차의 남은 시간 재개, 15초 연결 장애 판정, 장애 중단 시 자리 10분 유지, 실시간 STT 자막, 권한 직접 해제 종료 오버레이(OV-07), 신규 지원 알림 제거를 반영했습니다. 당시의 AI 판정 검증 규칙은 v0.5에서 변경되었습니다.

#### v0.5 — AI 판정·STT 장애 처리 및 문서 우선순위 정비

- **AI 판정(D-06):** AI가 총점·합격 기준·근거를 참고해 판정하며, 시스템은 형식·값 범위·근거를 검증합니다. 검증 실패 시 1회 재시도 후에도 실패하면 '확인 필요'로 처리합니다.
- **STT 실패(D-02):** 2회 재시도 후 최종 실패하면 '장애 중단'으로 처리하고, 마이페이지·S-A15 재점검을 거쳐 중단된 질문을 처음부터 다시 진행합니다. OV-04는 삭제했습니다.
- **문서 우선순위:** TRD → 화면정의서 → PRD → 시나리오 기획서 → 플로우차트. 상충 사항은 팀 결정 후 기록합니다.

#### v0.6 — 실제 구현(`huge/`) 대조 및 화면 상세 정비

- **AI 공고 생성 경로:** `/admin/postings/ai`로 명시하고, `/admin/postings/new`를 **작성 방식 선택 화면**으로 분리했습니다. 직접 작성은 `?mode=manual`로 진입합니다.
- **공고 미리보기:** S-R04를 별도 라우트가 아닌 **S-R03의 3단계 미리보기**로 통합했습니다.
- **지원자 이력서:** 제출 단계의 실제 버튼 문구 **[이력서 제출]**을 반영했습니다.
- **알림 UI:** 🔔 알림 숨기기 동작을 반영했습니다.
- **비밀번호 찾기:** 재설정 과정의 `/confirm` 경로를 반영했습니다.
- **회원 탈퇴:** `POST /me/withdraw` 연계를 반영했습니다.
- **동의 철회:** 응시 취소 안내 오버레이를 **§8.9**에 추가했습니다.
- **AI 공고 입력:** S-R02의 '주로 맡을 일'을 **필수에서 선택 항목**으로 변경했습니다(U6).
- **구현과 문서의 충돌 관리:** 구현을 기준으로 무조건 덮어쓰지 않고, **H-01~H-10**을 별도로 정리했습니다.

### 구현과 불일치하여 팀 결정이 필요한 항목 (§1.3)

| ID | 검토 항목 | 핵심 차이 |
|---|---|---|
| H-01 | AI 1차 판정 | AI 직접 판정 vs 구현의 총점·합격 기준 비교 |
| H-02 | 회사명 | 공고별 회사명 입력·표시 vs 단일 기업 전제 |
| H-03 | 회사 소개 | 명칭·필수 여부 차이 |
| H-04 | 준비 중 상태 | '준비 중' vs '면접 준비 중' |
| H-05 | 지원 브라우저 | 최신 2개 버전 vs Chrome·Edge 120 이상 |
| H-06 | 공고 불러오기 | 화면·API 정의 존재 vs 구현 없음 |
| H-07 | 이력서 상세 | 원본 파일·OCR 신뢰도 표시 vs 구현의 간소화된 정보 |
| H-08 | 답변 음성 전송 | WebRTC vs WebSocket PCM 전송 |
| H-09 | 장애 이어가기 | 횟수 제한 없음 vs 구현의 3회 제한 |
| H-10 | OV-05 문구 | 원인을 단정하지 않는 안내 vs 동시 면접 인원으로 원인 특정 |

**주의:** 위 항목은 v0.6에서 확정·해결된 사항이 아닙니다. 화면정의서 본문에는 기존 기준을 유지했으며, 관련 PRD·TRD와 함께 팀 검토가 필요합니다.

### 주요 화면 설계 원칙

1. **명확한 사용자 동선:** 화면마다 주 버튼과 자동 전환 조건을 구분합니다.
2. **서버 기준 상태 관리:** 응시 상태, 마감 시각, 남은 시간, 판정 결과는 서버 데이터를 기준으로 표시합니다.
3. **역할별 접근 제어:** 지원자·관리자 경로 및 API 접근 권한을 분리합니다.
4. **응시 화면의 연속성:** 면접과 코딩테스트는 동일 라우트 내 `phase`로 전환합니다.
5. **일관된 장애·예외 처리:** 장애 중단, 이탈, 동의 철회, 마감 등 후속 동작을 명시합니다.
6. **문서 간 추적성:** 화면 ID, 전환 ID, API, PRD 요구사항 및 인수 기준을 연결합니다.

### 문서 활용 방향

본 문서는 공통 UI/UX 설계 및 화면 구현 기준으로 사용합니다. 팀원은 공통 문서를 참고하여 개별적으로 구현할 수 있으나, **실제 구현과 기준 문서의 차이**를 확인하고 변경이 필요한 정책은 팀 검토를 거쳐 반영해야 합니다.

특히 v0.6의 라우트·버튼·화면 통합 사항은 개발 및 테스트에 참고하되, §1.3의 H 항목은 **구현 완료 또는 정책 확정으로 간주하지 않습니다.**

### 향후 검토 사항

- **H-01~H-10:** 구현과 PRD·TRD 사이의 불일치에 대한 팀 결정 및 후속 문서·코드 반영
- **기존 문서 상충(D):** STT 최종 실패, AI 판정, 결과 문의 안내 등 관련 문서 문구 정합성 확인
- **가정(G):** 작성 중 상태, 응시 재진입, 모바일 제한, 화면 이탈 중 재이탈 등 미확정 정책 검토
- **기술 연계:** §12의 TRD 반영 필요 API·필드 검토 및 실제 서버 계약과 비교
- **테스트:** 라우트 가드, 전체 화면 유지, 연결 장애·이어가기, 동의 철회, 마감 및 관리자 공고 작성 흐름 검증
- **추적성:** §13 미결 사항 및 PRD 인수 기준(AC)과 화면 구현의 대응 여부 확인

※ **v0.6은 실제 구현 대조 결과를 일부 반영한 초안**입니다. 구현과 다른 문서가 충돌하는 항목은 의도적으로 보류했으며, 팀 결정 및 후속 검증에 따라 변경될 수 있습니다.
