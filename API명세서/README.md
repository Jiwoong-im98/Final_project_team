## 2. 문서 개요

본 문서는 AI 기반 1차 채용면접 자동화 플랫폼에서 프런트엔드(Next.js)와 백엔드(FastAPI)가 연동하기 위한 **REST API 64개와 면접 실시간 메시지 23종**의 통신 규격을 정리한 명세서입니다.

각 기능의 요청 경로, 인증 및 접근 권한, 요청·응답 데이터 형식, 오류 코드, 실시간 메시지 처리 기준을 정의합니다.

v1.1에서는 기존 명세서를 바탕으로 팀원들의 리뷰 의견과 화면정의서 v0.4의 변경 사항을 반영하였습니다.

특히 **미디어 파일 제공, 응시 중 화면 이탈, STT 실패 처리, 공고 수정 이력, 브라우저 종료 이벤트 및 프록시 설정**에 대한 규칙을 구체화하였습니다.

데이터베이스의 개별 필드와 테이블 구조는 별도의 **ERD 및 테이블 정의서**를 참고하며, 실제 개발 과정에서 해당 문서와의 정합성을 확인할 예정입니다.

## 3. 작성 목적

- **프런트엔드·백엔드 연동 기준 통일:** API 경로, 요청·응답 데이터 및 처리 규칙 공유
- **인증·접근 권한 명확화:** 지원자, 관리자 및 면접 세션별 접근 범위 정의
- **실시간 면접 통신 규격 정리:** WebSocket 및 WebRTC 메시지와 처리 순서 정의
- **미디어 처리 방식 구체화:** 질문 음성, 답변 음성 및 녹화 파일의 접근·전송·보관 규칙 정의
- **예외 상황 대응:** 오류 코드, 재시도, 장애 복구 및 응시 종료 조건 정리
- **관련 문서 정합성 점검:** PRD·TRD·화면정의서·기술 아키텍처 간 불일치 식별
- **구현 준비:** 각 팀원이 공통 API 설계를 참고하여 개별 프로그램을 구현할 수 있도록 기준 제공

## 4. 주요 기술 및 공통 규칙

| 구분 | 설계 기준 |
|---|---|
| 프런트엔드 | Next.js |
| 백엔드 | FastAPI |
| REST API | `http://127.0.0.1:8080/api` |
| API 프록시 | Next.js rewrites를 통해 FastAPI 서버로 전달 |
| 미디어 파일 | `/media/*` 경로를 통해 권한 확인 후 제공 |
| 실시간 메시지 | WebSocket `ws://127.0.0.1:8000/ws/interview/{session_id}` |
| 실시간 음성 | WebRTC, UDP 40000~40019 |
| 인증 | HttpOnly, SameSite=Lax 쿠키 세션 |
| 데이터 검증 | Pydantic 모델, 미정의 필드 거부 |
| 데이터 교환 | JSON, 파일 업로드는 `multipart/form-data` |
| 오류 응답 | `{"code", "message"}` |
| 접속 범위 | 동일 PC의 `127.0.0.1` 환경 |
| 미디어 저장 | MinIO 기반 파일 저장 및 API 경유 제공 |

### v1.1 공통 규칙 보완

**1. 접속 호스트 통일**

- 브라우저 접속 주소를 `127.0.0.1`로 통일
- `localhost:8080` 접속 시 `127.0.0.1:8080`으로 리다이렉트
- WebSocket Origin 검사 및 쿠키 인증 기준 명확화

**2. 프록시 및 파일 전송**

- `/api/*`와 `/media/*`의 프록시 전달 경로 구분
- 미디어 파일에 대한 HTTP Range 요청 및 206 응답 지원
- 대용량 파일 업로드 시 프록시 본문 크기 제한 검토
- 처리 시간이 긴 API의 프록시 응답 시간 제한 검증 필요

**3. 데이터 및 보안**

- Pydantic 기반 요청·응답 데이터 검증
- 개인정보의 LLM 입력 및 Redis 메시지 포함 제한
- 지원자 본인 데이터 접근 검증
- 관리자 권한과 면접 세션 접근 권한 구분

※ 위 설정은 현재 문서의 로컬 실행 환경 기준이며, 외부 접속 및 배포 환경에 대한 설정은 별도 검토가 필요합니다.

## 6. v1.1 주요 변경 사항

### 6.1. 실시간 메시지 규격 확대

기존 22종에서 **23종으로 확대**되었습니다.

- STT 최종 변환 실패 이후의 재시도 메시지 `stt_retry` 추가
- 질문 재전송과 답변 시간 초기화 규칙 구체화
- STT 재시도 횟수 상한에 대한 제안 추가
- 장애 중단 시 `paused` 메시지와의 연계 기준 정리

현재 v1.1에서는 STT 변환이 재시도 이후에도 실패하면 `stt_retry`를 전송하고 같은 질문을 다시 진행하는 방식으로 정의하였습니다.

다만 이 처리 방식은 화면정의서 v0.5의 장애 중단 정책과 다르므로 후속 정합성 검토가 필요합니다.

### 6.2. 미디어 파일 제공 API 및 접근 권한 보완

**추가 API: `GET /media/{kind}/{path}`**

- 질문 음성, 답변 음성 및 녹화 파일 제공 경로 정의
- 지원자와 관리자별 미디어 접근 권한 구분
- MinIO 파일을 FastAPI 서버가 확인 후 전달
- HTTP Range 요청을 통한 구간 재생 지원
- 관리자 답변 음성 및 녹화 재생 시 감사 로그 기록
- 파일 보관 기간 만료 시 410 `MEDIA_EXPIRED` 반환

### 6.3. 공고 수정 정책 및 변경 이력 관리

- 게시 중인 채용공고의 수정 가능 항목 제한
- 허용되지 않은 항목 수정 시 `FIELD_LOCKED_AFTER_PUBLISH` 반환
- 수정 내용을 `posting_revisions`에 기록
- 공고 상세 응답에 `revisions[]` 추가
- 지원자 화면에서 공고 변경 사항과 수정 시각 표시

이를 통해 게시 이후 공고 변경 사항을 확인할 수 있도록 API 구조를 보완하였습니다.

### 6.4. 면접 화면 이탈 및 음성 처리 규칙 개선

- 1회차 화면 이탈 시 답변 시간 일시정지
- 경고창 확인 후 남은 답변 시간부터 재개
- 이탈 전후 답변 음성을 하나의 답변으로 처리
- 경고창이 표시되는 동안 수신한 음성 데이터 폐기
- 일시정지 상태에서의 Heartbeat 누락 처리 예외 추가
- 경고창 표시 중 재이탈 시 2회차 이탈로 처리하는 임시 규칙 반영

### 6.5. 브라우저 종료 이벤트 처리 보완

**관련 API: `POST /interview/{sid}/events`**

- 브라우저 종료·새로고침·페이지 이동 이벤트 수신
- `sendBeacon`을 이용한 종료 신호 전송
- Content-Type 차이에 따른 요청 파싱 오류 대응
- 종료 직전 이벤트를 `session_events`에 기록
- 장애 여부 판단에 필요한 이벤트 수집 기준 정리

기술 아키텍처의 예시 경로와 실제 API 명세서의 경로가 다른 부분은 후속 문서 수정 대상으로 관리합니다.

### 6.6. 관리자 알림 및 운영 기능 정비

- 신규 지원 알림 `new_application` 제거
- 결과 공개, 마감 안내, 데이터 삭제 예정 및 '확인 필요' 알림 중심으로 구성
- 관리자 운영 현황 및 분석 상태 조회 기준 보완
- 재처리 대상과 오류 사유 구분
- 운영 설정 변경 이력 및 동시 면접 상한 관리 기준 정리

### 6.7. 기술 구현 검토 항목 추가

- Next.js 프록시의 요청 본문 크기 제한 검토
- 장시간 실행 API의 응답 시간 제한 확인
- 미디어 파일의 접근 권한 및 Range 요청 처리 검증
- WebSocket Origin 및 쿠키 인증 동작 확인
- 로컬 실행 환경과 외부 배포 환경의 차이 검토

## 7. 핵심 설계 원칙

### 역할별 접근 권한

지원자는 본인의 지원 내역과 응시 정보에만 접근할 수 있으며, 관리자는 별도의 관리자 권한 검증을 거쳐 관련 데이터를 조회합니다.

면접 및 코딩테스트 API는 로그인 쿠키와 면접 세션 정보를 함께 확인합니다.

### AI 면접과 실시간 처리

질문, 자막, 진행 상태, 연결 확인 및 제어 메시지는 **WebSocket**으로 처리하고, 답변 음성은 **WebRTC**로 전송합니다.

연결 장애, 화면 이탈 및 장치 오류는 별도 이벤트와 상태 값으로 구분합니다.

### 이력서 처리

PDF·JPG·PNG 파일을 입력받아 텍스트 추출 및 필요한 경우 OCR을 수행합니다.

지원자가 추출 결과를 확인·수정하고 이력서를 확정하면 해당 지원의 이력서 사본을 저장하고 면접 질문 구성을 시작합니다.

### 평가 결과 및 관리자 권한

AI가 수행한 1차 합격·불합격 판정은 관리자 화면에서 조회할 수 있으나, **관리자가 판정 결과를 직접 수정하는 API는 제공하지 않습니다.**

관리자는 내부 메모, 운영 설정 및 '확인 필요' 건의 재처리를 수행할 수 있습니다.

AI 판정 결과에 대한 자동 검증 방식은 최신 화면정의서와의 정책 일치 여부를 추가 검토해야 합니다.

### 오류 및 장애 대응

공통 오류 응답 형식을 적용하고, 응시 상태에 따라 면접 시작, 재접속, 마감 및 취소 가능 여부를 판단합니다.

동시 면접 상한 초과 시에는 응시 횟수를 소모하지 않고 재시도를 안내합니다.

## 8. 관련 문서 및 변경 관리

본 API 명세서 v1.1은 다음 문서를 기준으로 작성되었습니다.

- TRD v1.5
- PRD v1.3
- 화면정의서 v0.4
- 기술 아키텍처 v1.0

원본 문서에서 **➕ 표시가 붙은 API**는 TRD에 명시되지 않았으나 화면정의서 등의 요구사항을 반영하여 추가한 항목입니다.

해당 API는 추후 TRD 및 관련 문서 개정 과정에서 반영 여부를 확인할 예정입니다.

### 8.1. 확인 필요 사항 확대

기존 A-01~A-13에 이어 v1.1에서는 A-14~A-19 항목이 추가되었습니다.

| 항목 | 검토 내용 |
|---|---|
| A-14 | AI 판정 검증 방식과 TRD 간 정책 차이 |
| A-15 | 신규 지원 알림 제거에 따른 PRD 반영 |
| A-16 | Next.js 프록시 본문 크기 및 응답 시간 제한 |
| A-17 | 화면 이탈 경고창 표시 중 재이탈 처리 |
| A-18 | 게시 후 공고 수정 가능 범위 및 변경 이력 |
| A-19 | `sendBeacon` 수신 경로와 기술 아키텍처 간 불일치 |

### 8.2. 최신 화면정의서 v0.5와의 정합성 검토

API 명세서 v1.1은 화면정의서 v0.4를 기준으로 작성되었으므로, 이후 작성된 화면정의서 v0.5와 일부 정책 차이가 존재합니다.

**1. AI 합불 판정 검증**

- API 명세서 v1.1: AI 판정과 합격 기준이 불일치하면 재판정 후 `needs_review`로 처리
- 화면정의서 v0.5: 점수와 합격 기준을 재비교하지 않고 형식·값 범위·근거 문장을 검증

**2. STT 최종 실패 처리**

- API 명세서 v1.1: `stt_retry`를 전송하고 동일 질문을 재진행
- 화면정의서 v0.5: 최종 실패를 시스템 장애로 분류하고 응시를 중단한 후 재접속 경로로 처리

위 두 항목은 실제 구현 시 응시 상태와 화면 전환에 직접적인 영향을 주므로, API 명세서 수정 과정에서 우선적으로 검토할 예정입니다.
