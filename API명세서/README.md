## 2. 문서 개요

본 문서는 AI 면접 프로젝트에서 프런트엔드(Next.js)와 백엔드(FastAPI)가 연동하기 위한 **REST API 64개와 면접 실시간 메시지 22종**의 통신 규격을 정리한 명세서입니다.

각 기능의 요청 경로, 인증·권한, 요청 및 응답 형식, 오류 코드와 실시간 메시지 처리 기준을 정의합니다. 데이터베이스의 개별 필드 및 테이블 구조는 별도의 **테이블 정의서**를 기준으로 합니다.

## 3. 작성 목적

- **프런트엔드·백엔드 연동 기준 통일:** 화면과 서버가 사용하는 API 경로, 데이터 형식 및 응답 규칙 공유
- **인증·접근 권한 명확화:** 지원자·관리자·면접 세션별 접근 범위 정의
- **실시간 면접 통신 규격 정리:** WebSocket 및 WebRTC 메시지와 처리 순서 정의
- **예외 상황 대응:** 오류 코드, 재시도, 장애 복구 및 응시 종료 조건 정리
- **관련 문서 정합성 점검:** PRD·TRD·화면정의서의 차이와 추가 API 요구사항 식별

## 4. 주요 기술 및 공통 규칙

| 구분 | 설계 기준 |
| --- | --- |
| 프런트엔드 | Next.js |
| 백엔드 | FastAPI |
| REST API | `http://127.0.0.1:8080/api` (Next.js rewrites를 통해 API 서버로 전달) |
| 실시간 메시지 | WebSocket `ws://127.0.0.1:8000/ws/interview/{session_id}` |
| 실시간 음성 | WebRTC, UDP 40000~40019 |
| 인증 | HttpOnly, SameSite=Lax 쿠키 세션 |
| 데이터 검증 | Pydantic 모델, 미정의 필드 거부 |
| 데이터 교환 | JSON (파일 업로드는 `multipart/form-data`) |
| 오류 응답 | `{"code", "message"}` 형식 |
| 접속 범위 | 현재 설계상 동일 PC의 `127.0.0.1` 환경 |

※ 위 주소 및 설정은 **현재 명세서의 로컬 실행 기준**이며, 외부 PC 접속 또는 배포 환경을 위한 설정으로 확정된 것은 아닙니다.

## 6. 핵심 설계 원칙

### 역할별 접근 권한

지원자 API는 로그인한 본인의 데이터에만 접근할 수 있도록 제한하며, 관리자 API는 별도의 관리자 권한 검증을 적용합니다. 면접·코딩테스트 API는 로그인 쿠키와 면접 세션 정보를 함께 확인합니다.

### AI 면접과 실시간 처리

질문·자막·진행 상태·연결 확인은 **WebSocket**으로 처리하고, 답변 음성은 **WebRTC**로 전송합니다. 연결 장애 및 화면 이탈은 별도 이벤트와 상태 값으로 구분합니다.

### 이력서 처리

PDF·JPG·PNG 파일을 입력받아 텍스트 추출 및 필요한 경우 OCR을 수행합니다. 지원자가 추출 결과를 확인·수정하고 이력서를 확정하면, 해당 지원의 이력서 사본을 저장하고 면접 질문 구성을 시작합니다.

### 평가 결과 및 관리자 권한

AI가 수행한 1차 합불 판정은 관리자 화면에서 조회할 수 있으나, **관리자가 판정 결과를 직접 수정하는 API는 제공하지 않습니다.** 관리자는 내부 메모, 운영 설정 및 '확인 필요' 건의 재처리를 수행할 수 있습니다.

### 오류 및 장애 대응

공통 오류 응답 형식을 적용하고, 응시 상태에 따라 면접 시작·재접속·마감·취소 가능 여부를 판단합니다. 동시 면접 상한 초과 시에는 응시 횟수를 소모하지 않고 재시도를 안내합니다.
