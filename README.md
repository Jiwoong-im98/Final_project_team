# AI 면접 프로젝트

> **기준일:** 2026년 11월 3일  
> **진행 단계:** 공통 설계 문서 최종 기준본 확정 및 개별 구현 진행  
> **문서 운영:** 공통 GitHub는 설계 기준본·작업 이력 보관, 이후 구현 및 문서 수정은 개인 GitHub에서 관리

## 1. 프로젝트 개요

본 프로젝트는 **AI 기반 1차 채용면접 자동화 플랫폼**을 기획하고 구현하는 것을 목표로 합니다. 지원자의 채용공고 확인 및 지원부터 AI 면접, 코딩테스트, 자동 평가, 결과 확인까지의 과정을 하나의 서비스로 구성합니다.

팀원들은 공통 기획·설계 문서를 함께 작성하고 검토하였으며, **해당 문서들을 개별 프로그램 구현에 활용하는 최종 기준 버전(Baseline)**으로 정리하였습니다. 이후의 프로그램 개발은 각 팀원이 독립적으로 수행합니다. 공통 문서 작성은 동일한 코드베이스나 단일 프로그램의 공동 개발을 의미하지 않습니다.

### 1.1. 프로젝트 진행 원칙 및 문서 관리 방침

1. **공통 문서 작업 마무리:** 공통 GitHub에 정리된 기획·설계 문서는 개별 구현을 위한 최종 기준본으로 활용합니다.
2. **개별 프로그램 구현:** 각 팀원은 공통 기준본을 참고하되, 기능 구현, 기술 스택, 개발 순서 및 세부 설계는 개인별로 결정합니다.
3. **개인 GitHub 활용:** 구현 소스코드, 실행 환경, 개발 이력, 개별 README 및 후속 수정 문서는 각자의 **개인 GitHub 저장소**에서 관리합니다.
4. **문서 수정의 개인 책임:** 구현 과정에서 발견한 기능 누락, 기술적 제약, 설계 변경 및 오류에 따른 문서 수정은 **각 팀원이 필요에 따라 직접 수행**하며, 해당 수정본은 개인 GitHub에 반영합니다.
5. **공통 문서의 역할:** 공통 GitHub의 기준본은 설계 출발점과 공동 작업 이력을 보존합니다. 개인별 변경 사항을 공통 문서에 일괄 반영하거나, 모든 팀원이 동일한 방식으로 구현할 의무는 없습니다.
6. **버전 및 이력 구분:** 공통 기준본의 버전과 개인 구현본의 버전은 별도로 관리합니다. 개인별 수정은 공통 기준본의 공식 변경을 뜻하지 않습니다.

> **'최종 기준 버전'의 의미:** 공동 설계 단계에서 개별 구현의 출발점으로 채택한 문서 버전입니다. 모든 정책의 오류가 해소되었거나, 향후 수정이 금지되었다는 뜻은 아닙니다. 이후 수정·보완이 필요하면 각자의 구현 환경과 판단에 따라 개인 저장소에서 진행합니다.

### 2.1. 화면정의서 v0.6 주요 반영 내용

- 실제 구현(`huge/`)과 화면 단위로 대조하여 버튼 문구, 라우트, 화면 흐름을 정리했습니다.
- AI 공고 생성 경로 `/admin/postings/ai`, 공고 작성 방식 선택 화면, 공고 미리보기의 작성 3단계 통합을 반영했습니다.
- 이력서 제출 버튼, 비밀번호 재설정 `/confirm`, 회원 탈퇴 `POST /me/withdraw`, 동의 철회 오버레이 등 구현 관련 변경을 반영했습니다.
- 구현과 다른 문서의 요구사항이 충돌하는 **H-01~H-10** 항목은 임의로 통일하지 않고 별도 기록했습니다.

이러한 미결 사항은 공통 기준본에 기록된 검토 과제이며, 이후 개인 구현 과정에서 필요에 따라 검토·조정할 수 있습니다. 개별 구현의 결정이 자동으로 공통 정책이 되지는 않습니다.

## 3. 공통 문서 관리 자료

### 3.1. 파일관리대장 (Document Register)

공통 문서의 목록, 디렉토리별 분류, 파일 위치, 버전 및 관리 이력을 확인하기 위한 자료입니다. **공통 기준본의 구성과 위치를 확인하는 용도**로 유지하며, 개인 구현 과정의 신규 문서와 수정본은 개인 GitHub에서 관리합니다.

### 3.2. WBS 업무관리 (Work Breakdown Structure)

공통 설계 단계의 담당 업무, 예정·실제 일정, 진행 상태를 확인하기 위한 관리 자료입니다. **개인별 구현 일정과 진행 현황은 각자 관리**하며, 기존 공통 WBS를 모든 개인 프로젝트의 통합 일정표로 사용하지 않습니다.

### 3.3. 회의록 (Meeting Minutes)

공통 설계 과정의 논의, 합의, 기술 검토 및 후속 조치를 기록한 자료입니다. 공동 설계가 어떤 판단을 거쳐 정리되었는지 확인하는 이력으로 활용합니다.

### 3.4. 피드백노트 (Feedback Notes)

공통 설계 당시의 오류·누락·개선 의견과 검토 내역을 확인하는 자료입니다. **개별 구현 이후의 수정과 피드백은 개인 저장소의 문서·이슈·커밋 이력 등으로 관리**할 수 있습니다.

## 4. 개별 구현 단계 운영

### 4.1. 구현 범위

각 팀원은 공통 문서를 출발점으로 삼아 프론트엔드, 백엔드 API, 데이터베이스, AI 질문 생성·면접, STT·TTS, 코딩테스트, 평가·판정, 관리자 기능, 테스트 및 배포 등을 개별적으로 구현합니다. 모든 기능을 같은 기술이나 구조로 구현할 필요는 없습니다.

### 4.2. 개인 GitHub 관리

개인 GitHub 저장소에서 다음 내용을 각자 관리합니다.

- 소스코드, 환경 설정, 실행 및 배포 방법
- 개인별 README, 구현 범위 및 진행 현황
- 공통 기준본을 바탕으로 수정한 PRD·TRD·화면정의서·API 명세서 등 필요한 문서
- 테스트 결과, 버그 수정, 설계 변경 및 버전 이력

**공통 GitHub는 기준 문서와 공동 작업 이력의 보관 장소이며, 개별 구현 결과물을 반드시 공통 저장소로 병합하는 방식은 아닙니다.**

### 4.3. 구현 이후 문서 수정 원칙

개발 중 공통 기준본과 실제 구현 사이에 차이가 발생할 수 있습니다. 각 팀원은 자신의 구현 내용에 맞게 관련 문서를 자유롭게 수정·보완할 수 있으며, 수정 여부와 범위, 반영 시점은 개인이 판단합니다. **수정된 문서와 프로그램은 개인 GitHub에 기록하고 관리**합니다.

개인 저장소에서 이루어진 변경은 다른 팀원의 구현이나 공통 기준본에 자동으로 적용되지 않습니다. 따라서 공통 기준본과 개인 구현본의 차이는 각 개인 프로젝트의 문서 및 변경 이력으로 구분합니다.

## 5. 프로젝트 진행 요약

**2026년 11월 3일 기준**, 공통 설계 문서의 공동 작성·정리 단계를 마무리하고, 해당 문서를 **개별 구현을 위한 최종 기준 버전**으로 활용하는 단계입니다.

이후 팀원들은 공통 문서를 참고하여 **각자의 개인 GitHub에서 독립적으로 프로그램을 개발**합니다. 구현 과정에서 필요한 기능 변경, 기술적 보완, 문서 수정 및 테스트 결과 관리는 **각 개인이 책임지고 수행**합니다.

> **운영 원칙 요약:** 공통 문서는 구현의 출발점으로 유지하고, 이후 프로그램 구현과 관련 문서의 수정·버전 관리는 개인별 GitHub에서 독립적으로 진행합니다.
