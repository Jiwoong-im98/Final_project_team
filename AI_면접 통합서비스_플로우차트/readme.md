# AI 면접 통합 서비스 플로우차트

## 2. 문서 개요

본 문서는 AI 기반 1차 채용면접 자동화 플랫폼의 전체 서비스 흐름과 기능별 처리 절차를 정리한 통합 플로우차트입니다.

각 팀원이 개별적으로 작성한 플로우차트를 바탕으로 공통 기능과 처리 흐름을 통합하였으며, 이후 PRD 및 TRD의 요구사항을 반영하여 지속적으로 수정하고 있습니다.

전체 서비스 흐름뿐 아니라 회원가입, 채용공고, 지원 절차, 질문 생성, AI 면접, 코딩테스트, 평가, 결과 공개, 장애 처리 및 부정행위 대응까지 포함합니다.

현재 08v에서는 **PRD 요구사항 ID와 TRD 기술 처리 기준을 연결**하여 각 기능의 구현 근거와 검증 대상을 확인할 수 있도록 구성하였습니다.

플로우차트는 Mermaid 형식으로 작성하여 GitHub에서 직접 확인하고 버전별 변경 사항을 관리할 수 있도록 하였습니다.

## 3. 작성 목적

- **서비스 흐름 파악:** 화면 간 이동, 기능 호출, 조건 분기 및 복귀 경로 확인
- **기능 범위 검토:** 필수 기능의 누락과 불필요한 기능의 포함 여부 검토
- **팀원 간 설계 기준 공유:** 개별적으로 작성한 설계를 공통 흐름으로 정리
- **AI 처리 절차 구체화:** 질문 생성, 꼬리질문, 자동 평가 및 합불 판정 흐름 정의
- **예외 상황 대응:** 네트워크 장애, 시스템 오류, 재접속 및 부정행위 처리 기준 정리
- **문서 정합성 확보:** PRD·TRD와 플로우차트 간 요구사항 및 처리 규칙 비교

## 5. 버전별 변경 이력

### 05v — GitHub 최초 등록 버전

**상태:** 최초 등록 / 내부 검토본

05v는 팀 내 논의를 통해 작성한 통합 서비스 플로우차트의 최초 GitHub 등록 버전입니다.

이전 설계 과정에서 논의된 화면 이동, 질문 생성, 코딩테스트, 평가 및 관리자 기능을 통합하였으며, 질문 생성 과정의 무한 재시도 가능성을 개선하였습니다.

**주요 반영 내용**

- 지원자와 관리자 로그인 이후 진입 화면 분리
- 공고 목록·상세·지원하기 절차 구체화
- 관리자 수동 질문 작성 기능 제거
- 질문은행 및 LLM 기반 자동 질문 생성 적용
- 코딩테스트의 LLM 보조 기능 제거
- AI 자동 평가 및 관리자 모니터링 역할 구분
- 질문별 꼬리질문 생성 조건과 횟수 제한 설정
- 질문 생성 시 개별 재시도 및 전체 생성 사이클 상한 추가
- 전체 생성 실패 시 공고 보류 및 관리자 확인 경로 정의

### 06v — PRD 기반 서비스 흐름 전면 개편

**주요 변경 내용**

- PRD v1을 기준으로 서비스 흐름 전면 재작성
- 도면을 00~12번의 기능별 구조로 재편성
- 질문 구성 과정에서 관리자 검토·승인 단계 제거
- 꼬리질문 상한을 질문당 1개, 전체 4개로 변경
- 코딩테스트 AI 도우미 기능 제거 유지
- 결과 공개를 공고 마감 다음 날 10:00 일괄 공개로 변경
- 공통 요구사항에 맞춰 응시·평가·관리자 흐름 정비

### 07v — PRD 팀 피드백 반영

**주요 변경 내용**

- AI가 1차 합격·불합격을 직접 판정하도록 변경
- 이메일 인증을 후순위 부가 기능으로 조정
- 질문 생성 실패 시 문항별 최대 3회 재생성 및 대체 질문 적용
- 동시 면접 처리량을 운영 설정값 N으로 관리
- 스캔 PDF 이력서의 온프레미스 OCR 처리 경로 추가
- PRD 용어를 기준으로 도면 내 기능 명칭 통일

### 08v — TRD v1.5 연계 및 기술 처리 기준 구체화

**주요 변경 내용**

#### ① 관리자 및 서비스 운영 구조 통합

- 기업 담당자와 운영자를 단일 관리자 역할로 통합
- 설치 시 관리자 계정 1개를 생성하는 구조 반영
- 기업별 계정 및 데이터 분리 구조 제거

#### ② 공고 관리 및 지원 절차 보완

- Open API 및 JSON·CSV 더미 데이터를 활용한 공고 불러오기 추가
- 게시 이후 공고 내용 수정과 평가 기준 잠금 조건 구분
- 공고 마감 시 진행 중 응시를 즉시 종료하도록 변경
- 이력서 제출 형식을 PDF·JPG·PNG로 확대
- OCR 예상 처리 시간과 실패 판정 기준 추가
- 동시 면접 상한 초과 시 대기 상태 대신 재시도 안내 적용

#### ③ 질문 구성 및 AI 면접 개선

- 질문 생성 시점을 면접 시작에서 이력서 확정 직후로 변경
- 백그라운드 질문 생성 및 전체 60초 처리 제한 적용
- 질문 생성 시도당 8초 제한 및 실패 시 대체 질문 처리
- 꼬리질문 생성 여부를 고정 시간이 아닌 남은 처리 시간에 따라 판단
- TTS 생성 지연 시 자막만으로 질문을 제시하도록 보완

#### ④ AI 평가 및 합불 판정 기준 변경

- AI가 루브릭 평가 결과와 종합 점수를 참고하여 1차 합불 결정
- 시스템은 AI 판정의 형식, 값 범위 및 근거 문장을 검증
- 시스템이 합격 기준 점수로 AI 판정을 다시 결정하지 않도록 변경
- 평가 실패 시 재시도 및 '확인 필요' 상태 처리
- 관리자 승인 없이 검증된 AI 판정을 확정하는 구조 유지

#### ⑤ 결과 공개 및 개인정보 관리 개선

- 공고 마감 시각에 모든 응시가 종료되도록 처리
- 평가 지연 시 별도 결과 공개 일정 재설정
- 이메일 발송 실패 시 재시도 간격 구체화
- 결과 공개 이후 보관 기간 및 자동 삭제 절차 정리
- 지원자 마이페이지의 마감 관련 응시 상태 추가

#### ⑥ 장애 복구 및 화면 이탈 처리 보완

- Heartbeat 15초 누락 시 장애 여부 판단
- 공고 마감 시각까지만 응시 재접속 허용
- 장애 중단 시 동시 면접 자원을 최대 10분 유지
- 장애로 중단된 질문은 처음부터 다시 진행
- 화면 이탈 1회 발생 시 남은 답변 시간부터 재개
- 화면 이탈 전후 음성을 하나의 답변으로 합쳐 처리
- 화면 이탈 횟수는 면접과 코딩테스트에서 합산

## 6. 문서 활용 방향

본 플로우차트는 프로젝트의 **공통 서비스 설계 및 기능 처리 기준 문서**로 활용합니다.

PRD에서 정의한 요구사항과 TRD에서 제시한 기술 구현 방식을 서비스 흐름으로 연결하며, 실제 개발에 앞서 화면 전환과 내부 처리 절차를 검토하는 데 사용합니다.

각 팀원은 공통 플로우차트를 참고하여 개별적으로 프로그램 구현을 진행할 수 있으며, 기술 스택이나 구현 방식은 서로 다를 수 있습니다.

다만 핵심 서비스 흐름과 필수 기능의 처리 기준은 공통 문서를 바탕으로 검토합니다.

또한 개발 과정에서 발견되는 기능 누락, 처리 오류, 예외 상황 및 문서 간 불일치 사항은 팀원 간 논의를 거쳐 이후 버전에 반영할 예정입니다.

## 7. 향후 검토 및 보완 사항

08v에서는 이전 버전에서 미확정 상태였던 주요 설계 항목을 PRD 및 TRD 기준으로 정리하였습니다.

다만 다음 사항은 추가 검토가 필요합니다.

- **화면 이탈 후 재개 시간:** PRD v1.3의 답변 시간 재부여 기준과 TRD v1.5의 남은 시간 재개 기준 간 불일치
- **문서 간 정합성:** PRD 개정 시 플로우차트와 TRD의 요구사항 및 처리 규칙 일치 여부 확인
- **실제 구현 검증:** 비동기 질문 생성, 장애 복구, 동시 면접 제어 및 AI 평가 처리 흐름의 동작 검증
- **운영 성능 검증:** AI 모델 응답 시간과 서버 자원 제약에 따른 처리 기준 조정

※ 본 문서는 **08v 내부 검토본**이며, 05v를 GitHub 최초 등록 버전으로 하여 변경 이력을 관리합니다. 실제 개발 결과와 차이가 발생하는 경우 PRD·TRD 및 팀원 간 협의 결과를 바탕으로 수정할 예정입니다.
