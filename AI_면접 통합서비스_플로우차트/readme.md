AI 면접 통합 서비스 플로우차트
통합 설계 검토 보고서 | 05v (내부 검토본)

문서 개요
본 문서는 AI를 활용한 면접을 진행하기 위해 서비스 전체 흐름과 기능별 처리 절차를 정리한 통합 플로우차트 보고서이다.

작성 배경 및 문서의 성격
각 팀원은 담당 기능과 관점에 따라 서로 다른 플로우차트를 작성하였다. 일부 흐름과 세부 구현 방식에는 차이가 있으나, 본 문서는 팀 내 논의를 바탕으로 공통 흐름을 정리한 내부 검토 결과물이다. 실제 구현 결과와 차이가 발생할 수 있으며, 핵심 기능의 누락·중복·보완 사항을 검토하여 이후 버전에서 지속적으로 수정할 예정이다.

작성 목적
화면 연계 파악: 플로우차트를 통해 전체 화면과 기능이 어떤 조건에서 연결·전환·복귀하는지 명확히 파악한다.
기능 범위 점검: 사전에 정의한 기능을 확인하고, 불필요한 기능의 포함 여부와 필수 기능의 누락 여부를 검토한다.
팀원 간 인식 조율: 공통 플로우차트를 공유하여 결과물의 범위와 동작 방식에 대한 해석 차이를 줄인다.
AI 및 개발 환경 조율: AI 활용 지점과 필요한 라이브러리·프로그램·외부 환경을 확인하고, 버전 및 연동 방식을 조율한다.
해석 및 변경 관리 원칙
전체 흐름도는 화면 간 이동과 재진입을 나타내며, 기능별 도면은 내부 처리·조건 분기·실패·재시도 경로를 구체화한다. 도면의 처리 순서는 설계 기준이며, 실제 비동기 처리나 구현 상세는 개발 과정에서 조정할 수 있다.

01v 반영 사항: 02번 질문은행·RAG 생성 흐름에서 관리자 수동 질문 작성 경로를 제거했다. 질문 확보는 질문은행 자동 선택 또는 LLM 자동 생성으로 진행하며, 관리자 역할은 검토·승인에 한정한다.

02v 반영 사항:

00번 전체 흐름도 — 로그인 성공 후 도착 화면을 역할별로 분리했다. 지원자는 공고 목록으로, 관리자는 관리자 대시보드로 진입하며, 마이페이지는 별도 메뉴에서 접근한다. (기존에는 역할 구분 없이 “마이페이지”로 통합 진입하도록 되어 있었음)
01번 회원·공고·지원 흐름도 — 공고 목록 → 공고 상세 → 지원하기로 이어지는 지원자 화면 전환 단계가 누락되어 있어 추가했고, 관리자의 공고 작성/수정 경로와 지원자의 지원 경로를 분리해 혼동을 없앴다.
10번 지원자 마이페이지 흐름도 — “마이페이지·공고 목록”으로 합쳐져 있던 진입 화면을 “마이페이지” 단일 화면으로 정리하고, 공고 목록은 00/01번 흐름도의 화면을 그대로 참조하도록 분리했다.
이미지(PNG) 대신 Mermaid 코드로 전환해 깃/문서 도구에서 직접 편집·리뷰할 수 있도록 했다.
03v 반영 사항:

02번 질문은행·LLM 생성 — 기업 공개문서 검색(Retriever·pgvector, RAG) 단계를 제거했다. 질문은행에 적합한 질문이 부족하면 외부 문서 검색 없이 바로 LLM이 생성한다. 도면명도 “질문은행·RAG 생성” → “질문은행·LLM 생성”으로 변경했다.
04번 코딩테스트 응시 — LLM 보조 코드 작성 옵션(작업 방식 선택, LLM 사용 요청, 토큰·정책 허용 여부)을 전부 제거했다. 코딩테스트는 LLM 지원 없이 일반적인 코딩테스트로 진행한다. 도면명도 “코딩테스트 응시·LLM” → “코딩테스트 응시”로 변경했다.
10번 지원자 마이페이지 — 마이페이지에서 면접/코딩 응시 메뉴를 제거했다(응시는 마이페이지가 아닌 공고 상세에서 진행). 결과 공개 승인 여부를 묻던 분기도 제거해 결과·피드백을 바로 조회하도록 단순화했다.
01번 회원·공고·지원 — 공고 지원 버튼(면접 응시) 클릭 시 ① 개인정보 수집·이용 동의 → ② 이력서 PDF 제출·OCR 텍스트 추출 → ③ AI 면접 시작(03번 도면으로 연결)으로 이어지는 단계를 추가했다.
04v 반영 사항:

07번 면접 평가·리포트 — “담당자 승인?” 게이트를 제거했다. 합불은 관리자 개입 없이 AI가 고정 루브릭 가중합 점수와 사전 설정된 합격 기준점(threshold)을 기준으로 자동 확정하며, 판정 근거(세부 점수·루브릭 버전)는 감사 로그로 저장한다.
08번 관리자 대시보드 — 합불 결정 권한이 07번으로 이전됨에 따라 도면명을 “관리자 대시보드·결정” → “관리자 대시보드·모니터링”으로 변경했다. 지원자 메뉴는 AI 판정 결과·근거를 조회하고 이상 사례를 플래그하는 기능으로 한정하며, 관리자가 판정을 직접 변경하지는 않는다.
03번 AI 면접·꼬리질문 — “꼬리질문 필요?” 분기의 판단 기준을 구체화했다. ① 답변 충분성(STAR 요소·정량 지표 누락), ② 구체성 부족(모호한 답변·사례 없음), ③ 공고 요구 역량 커버리지 미달, ④ 이력서/자소서 내용과의 불일치 중 하나 이상에 해당할 때 꼬리질문을 생성한다. 무한 루프 방지를 위해 질문당 최대 2회, 세션 전체 최대 5회로 한도를 둔다.
05v 반영 사항:

02번 질문은행·LLM 생성 — “재시도 한도 초과 → 재시도 대기 → 재시도”로 이어지는 경로와 “반려 → 재생성” 경로에 상위 상한이 없어 무한 루프가 가능했던 문제를 수정했다. 개별 생성 시도 한도(최대 3회)와 별개로 전체 생성 사이클 한도(개별 재시도 초과·리뷰어 반려 포함 최대 5회)를 추가했으며, 전체 한도를 넘으면 더 이상 자동 재시도하지 않고 “질문 확보 실패 · 공고 보류(관리자 수동 개입 필요)” 상태로 종료한다.
