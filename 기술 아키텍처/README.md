# 기능정의서 (Functional Specification)

**문서명:** AI 1차 채용면접 자동화 플랫폼 기능정의서  
**파일명:** `Final_Project_기능정의서_0.2v.xlsx`  
**버전:** v0.2  
**작성일:** 2026년 10월 29일  
**진행 상태:** 초안 (Draft) / 문서 간 상충 사항 팀 검토 필요  
**기준 문서:** 통합 PRD v1.3 · 화면정의서 v0.2 · TRD v1.5

## 문서 개요

본 문서는 AI 기반 1차 채용면접 자동화 플랫폼에서 제공하는 기능을 개발 및 검증 가능한 단위로 정의한 문서입니다.

PRD의 요구사항 ID를 기준으로 기능명, 사용자, 상세 기능, 실행 방법, 입력값, 결과값, 예외사항, 상태 변경 및 관련 화면을 정리하였습니다. 하나의 요구사항을 여러 기능으로 구분할 경우 `-1`, `-2` 등의 하위 번호를 부여하여 추적할 수 있도록 구성하였습니다.

이를 통해 팀원별 구현 방식이 다르더라도 **핵심 기능의 동작 조건과 예외 처리에 대한 공통 기준**을 확인할 수 있도록 하는 것이 목적입니다.

## 주요 작성 내용

- **계정·인증(ACC):** 로그인, 회원가입, 비밀번호 정책, 관리자 계정, 세션 및 접근 권한
- **채용공고(JOB):** 공고 등록·조회·수정, AI 초안 생성 및 게시·마감 관리
- **지원 절차(APP):** 공고 탐색, 지원서 작성, 필수 동의, 이력서 OCR 및 사전 환경 점검
- **AI 면접(INT):** 질문 진행, 음성 답변, 꼬리질문, 동시 면접 입장 및 세션 관리
- **질문 구성(QST):** 질문은행, 질문 선정·생성, 중복 방지, 재시도 및 대체 질문
- **코딩테스트(COD):** 문제 응시, 코드 실행·저장, 시간 관리 및 채점
- **평가(EVL):** 면접 평가, 점수 계산, AI 합격·불합격 판정 및 결과 검증
- **결과·리포트(RPT):** 응시 완료 안내, 결과 공개, 피드백 및 열람
- **관리자(ADM):** 지원자 관리, 결과 조회, 비교, 통계 및 운영 설정
- **장애·복구(RES):** 연결 상태 감지, 장애 판정, 재접속 및 이어가기
- **부정행위(CHT):** 화면 이탈 등 응시 규칙 위반의 감지 및 처리
- **운영 정책(POL):** 공통 운영·관리 정책과 처리 기준
- **보안(SCR):** 개인정보 보호 및 보안 관련 기능

## v0.2 주요 변경 및 보완 사항

- **TRD v1.5 반영:** 기존 PRD v1.3 및 화면정의서 v0.2의 내용을 유지하면서 TRD v1.5에서 구체화된 기술·운영 기준을 추가하였습니다.
- **인증 및 보안:** 로그인 쿠키, 세션 유지, 비밀번호 해시, 관리자 초기 비밀번호 변경 및 권한 처리 기준을 보완하였습니다.
- **이력서 처리:** PDF·JPG·PNG 업로드, OCR 처리 시간 추정, 실패 기준 및 신뢰도 낮은 항목 표시 규칙을 정리하였습니다.
- **질문 생성:** 이력서 확정 직후 백그라운드 질문 구성, 생성 시간 상한, 재시도 및 대체 질문 적용 기준을 보완하였습니다.
- **실시간 면접 운영:** 동시 면접 상한, 질문·답변 시간, 꼬리질문 생성 제한 및 운영 장비 제약을 반영하였습니다.
- **서버 환경:** 단일 PC의 localhost 및 Docker Compose 운영 구성, 외부 통신 범위와 데이터 암호화 방식을 추가하였습니다.
- **문서 간 차이 표시:** PRD·화면정의서·TRD 사이에서 기준이 다른 항목은 기존 내용을 임의로 삭제하거나 통일하지 않고, 노란색 **⚠ 확인 필요** 표시로 구분하였습니다.

## 문서 작성 및 활용 원칙

본 기능정의서는 프로젝트의 **공통 기능 구현 및 테스트 기준 문서**로 활용합니다.

기능 ID는 PRD 요구사항과 연결되며, 각 기능의 실제 화면은 화면정의서의 `S-Cxx`(공통·인증), `S-Axx`(지원자), `S-Rxx`(관리자), `OV-xx`(응시 중 오버레이) 등 화면 ID로 추적합니다.

기능정의서의 입력값·결과값·예외사항은 API 명세서와 연계하여 검토하고, 상태 변경과 공통 규칙은 TRD 및 테스트 계획서의 구현·검증 기준으로 활용합니다.

팀원들은 공통 문서를 참고하되 개별적인 기술 스택과 구현 방식을 선택할 수 있습니다. 구현 과정에서 기능의 동작이나 예외 처리 기준을 변경할 필요가 생기면 관련 문서와의 일치 여부를 먼저 확인합니다.

## 향후 검토 사항

현재 v0.2는 초안이며, 특히 다음과 같은 **문서 간 불일치 또는 미확정 사항**은 팀 협의가 필요합니다.

- **로그인 후 복귀 경로:** TRD의 허용 URL 접두어와 화면정의서의 실제 화면 라우트 표기가 서로 다른 부분
- **이력서 OCR 예상 시간:** TRD의 계산식 기반 예상 시간과 화면정의서의 고정 구조화 시간 기준
- **접속·보안 환경:** TRD의 localhost·HTTP 운영 구성과 PRD의 외부 HTTPS 노출 기준
- **꼬리질문 판단 시간:** PRD의 고정 5초 기준과 TRD의 남은 처리 시간 기반 판단 방식
- **기타 ⚠ 확인 필요 항목:** 노란색으로 표시된 행의 정책 및 기술 기준 확정

검토 결과는 PRD, TRD, 화면정의서, API 명세서 및 기능정의서의 변경 이력에 함께 반영하여 문서 간 추적성을 유지할 예정입니다.

※ 본 문서는 **v0.2 초안 기준**이며, 실제 구현 및 테스트 과정에서 기능의 세부 동작과 기술적 처리 방식이 변경될 수 있습니다.
