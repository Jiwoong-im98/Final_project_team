## TRD (기술 요구사항 정의서)

**문서명:** AI 1차 채용면접 자동화 플랫폼 TRD  
**파일명:** `Final_Project_TRD_v1.5.pdf`  
**버전:** v1.5  
**최종 작성일:** 2026년 10월 29일  
**진행 상태:** 초안 (Draft) / 운영 서버 성능 검증 및 일부 기술 정책 확정 필요  
**기준 문서:** 통합 PRD v1.6

### 문서 개요

본 문서는 AI 기반 1차 채용면접 자동화 플랫폼의 기술 요구사항과 시스템 구현 방식을 정의한 문서입니다.

통합 PRD v1.6에서 정의한 기능과 운영 정책을 구현하기 위해 필요한 기술 스택, 시스템 아키텍처, 데이터 구조, API 인터페이스, 실시간 통신 및 AI 모델 운영 방식을 구체화하였습니다.

특히 VRAM 6GB·RAM 58GB의 단일 서버 환경에서 AI 면접, 코딩테스트, 자동 평가 및 합격·불합격 판정을 수행할 수 있도록 **기술적 실현 가능성, 시스템 안정성 및 운영 효율성**을 고려하여 설계하였습니다.

v1.5에서는 기존 기술 설계를 보완하여 **NGINX 없는 로컬 서버 운영, WebRTC 기반 실시간 음성 전송, LangGraph를 활용한 AI 처리 흐름, 장애 복구 및 동시 면접 자원 관리**를 구체화하였습니다.

또한 AI의 평가 결과를 시스템이 검증하되, 별도의 점수 규칙으로 합격 여부를 재판정하지 않도록 역할을 구분하였습니다.

### 주요 작성 내용

- **시스템 아키텍처:** Next.js, FastAPI, Celery, Celery beat 기반 서비스 구성 및 Docker Compose 배포 구조
- **기술 스택 정의:** Python, TypeScript, PostgreSQL, Redis, MinIO, LangChain, LangGraph 및 AI 모델 실행 환경
- **로컬 서버 구성:** 단일 PC의 localhost 환경에서 NGINX와 HTTPS 없이 운영하는 개발·시연 구조
- **데이터 설계:** 사용자, 채용공고, 지원서, 질문은행, 면접 답변, 평가 결과, 감사 로그 및 운영 설정 데이터 구조
- **API 및 실시간 통신:** REST API, WebSocket, WebRTC 기반 면접 진행, 실시간 자막 및 상태 관리
- **AI 모델 배치:** VRAM 6GB·RAM 58GB 환경에 맞춘 LLM, STT, TTS 및 임베딩 모델 배치
- **AI 면접 파이프라인:** LangGraph 기반 질문 생성, RAG 검색, 꼬리질문 판단, 답변 처리 및 이력서 OCR
- **AI 평가 및 판정:** 루브릭 기반 항목 평가, 점수 계산, AI 합격·불합격 결정 및 결과 유효성 검증
- **코딩테스트 실행 환경:** Docker 격리 실행, 인터넷 차단, 리소스 제한, 자동 저장 및 테스트케이스 채점
- **장애 및 예외 처리:** 연결 단절, 장치 오류, 화면 이탈, 서버 장애 및 면접 재접속 처리
- **동시 면접 관리:** Redis 기반 입장 제한, 면접 자원 반환, 장애 중단 시 자리 유지 및 자동 보호
- **보안 및 개인정보:** 접근 권한 검증, 데이터 암호화, 내부망 분리, 보관 기간 관리 및 자동 삭제
- **성능 및 테스트:** AI 응답 시간, 동시 면접 처리량, 모델 성능 측정 및 PRD 인수 기준 검증
- **운영 설정 관리:** 재시도 횟수, 타임아웃, 동시 면접 상한 및 결과 공개·삭제 설정값 중앙 관리

### v1.5 주요 변경 및 보완 사항

#### 1. 시스템 아키텍처 및 서버 운영 구조 구체화

- 통합 PRD v1.6을 기준으로 기술 요구사항과 시스템 구성 정비
- 단일 서버 PC에서 Docker Compose를 이용한 서비스 운영 구조 구체화
- NGINX와 HTTPS를 사용하지 않는 localhost 기반 접속 방식 정의
- Next.js의 API Rewrites를 통한 일반 HTTP 요청 전달 방식 적용
- FastAPI의 REST API·WebSocket 및 WebRTC 통신 경로 구분
- WebRTC 음성 전송용 UDP 포트 `40000~40019` 범위 정의
- Docker 네트워크를 frontend 연동망, 내부망, 외부 통신망으로 분리
- 다른 PC에서 접속하는 운영 환경으로 전환할 경우 HTTPS 및 네트워크 구성 재검토 필요

#### 2. AI 모델 및 기술 스택 구성 보완

- Next.js 16.x, React 19.x, Python 3.11 등 기술 버전 기준 정리
- llama.cpp 기반 Qwen3 모델 실행 및 GPU·CPU 역할 분리
- faster-whisper와 Whisper Large V3 Turbo를 활용한 STT 구성
- 한국어 TTS 후보 및 실패 시 텍스트 대체 방식 정의
- BGE-M3와 pgvector를 활용한 질문 검색·임베딩 구조 구체화
- PaddleOCR 기반 한국어 이력서 문자 인식 및 PDF 텍스트 추출 방식 정리
- LangChain·LangGraph를 통한 LLM 호출, 상태 관리 및 처리 흐름 설계

#### 3. 실시간 면접 통신 및 장애 처리 개선

- WebRTC를 통한 실시간 음성 전송과 WebSocket 기반 질문·자막·상태 통신 분리
- Redis Streams를 활용한 음성 조각 전달 및 STT 처리 구조 정의
- 실시간 임시 자막과 최종 STT 결과를 구분하여 처리
- Heartbeat 기반 연결 상태 감지 및 장애 판정 기준 구체화
- 창 닫기·새로고침·장치 권한 해제 등 사용자 동작과 네트워크 장애 구분
- 장애 중단 시 응시 상태와 남은 시간 저장 및 재접속 처리 기준 정리

#### 4. 동시 면접 및 서버 자원 관리 강화

- Redis와 Lua 스크립트를 활용한 동시 면접 입장 관리
- 동시 면접 상한 N을 운영 설정으로 관리하는 구조 정의
- AI 면접 종료 후 코딩테스트로 전환할 때 면접 자원을 반환하도록 설계
- 장애 중단 시 일정 시간 면접 자원을 유지하고 이후 반환하는 정책 추가
- 서버 상태와 실제 면접 수의 불일치를 정기적으로 보정
- GPU 메모리 사용률과 질문 응답 지연을 기반으로 신규 입장을 제한하는 자동 보호 방식 정의

#### 5. AI 질문 생성 및 평가 파이프라인 구체화

- Excel 기반 질문은행 적재 및 질문 분류·중복 제거 기준 정리
- RAG를 활용한 유사 질문 검색 및 LLM 질문 생성 절차 구체화
- LangGraph 기반 질문 생성·검증·재시도·대체 질문 처리 구조 정의
- 면접 진행 상태와 AI 처리 흐름을 분리하여 서버가 전환 규칙을 관리
- AI 평가 결과에 대한 JSON 형식, 점수 범위 및 근거 문장 검증 강화
- 평가 결과가 유효하지 않을 경우 재시도 또는 '확인 필요' 상태로 처리
- AI가 합격 여부를 결정하고 시스템은 결과의 유효성을 검증하도록 역할 구분

#### 6. 데이터 관리 및 운영 안정성 보완

- Pydantic 기반 요청·응답 및 LLM 출력 데이터 형식 통일
- 면접 질문, 이력서, 평가 기준의 스냅샷 및 버전 관리 원칙 정리
- 개인정보와 파일의 암호화 저장 및 자동 삭제 절차 구체화
- Celery worker와 scheduler를 활용한 비동기 작업 및 정기 작업 분리
- 운영 설정값을 중앙에서 관리하고 변경 이력을 기록하도록 설계
- PRD 요구사항과 기술 구현·테스트 항목 간 추적 관계 정비

### 문서 활용 방향

본 TRD는 프로젝트의 **공통 기술 설계 및 구현 기준 문서**로 활용합니다.

PRD에서 정의한 기능과 정책을 실제 프로그램으로 구현하기 위한 기술적 방향을 제시하며, 향후 기술 아키텍처, AI 아키텍처, API 명세서, ERD, 테이블 정의서 및 테스트 계획서 작성 시 참고 자료로 사용합니다.

각 팀원은 공통 기술 요구사항을 참고하여 개별적으로 프로그램 구현을 진행하며, 구현 방식이나 기술 선택은 개인별로 달라질 수 있습니다.

다만 사용자 인증, 응시 상태 관리, 장애 복구, 평가 결과 검증 및 개인정보 처리와 같은 핵심 요구사항은 공통 기준을 참고하여 구현합니다.

또한 실제 운영 서버에서 AI 모델의 메모리 사용량, 응답 속도, 동시 면접 처리량 및 장애 복구 기능을 측정하고, 검증 결과에 따라 기술 설계를 수정·보완할 예정입니다.

### 향후 검토 사항

현재 v1.5는 초안 단계로, 일부 기술 선택과 운영 설정에 대한 추가 검증이 필요합니다.

주요 검토 대상은 다음과 같습니다.

- **AI 모델 배치:** 실시간 면접용 GPU 모델과 평가용 CPU 모델의 성능 검증
- **동시 면접 상한:** 임시 설정값 N=2에 대한 실제 서버 부하 및 응답 시간 측정
- **한국어 TTS:** Supertonic 등 설치형 TTS의 음질과 처리 속도 검증
- **AI 판정 일관성:** 평가 기준과 AI 합격·불합격 결정 간 불일치 발생 빈도 측정
- **예비 질문은행:** 질문 유형별 예비 질문 확보 및 검증
- **OCR 성능:** PaddleOCR의 한국어 이력서 인식 정확도와 처리 시간 측정
- **운영 정책:** 코딩테스트의 동시 면접 상한 제외, 재시도 방식 및 이메일 인증 적용 범위에 대한 팀 협의
- **차별 표현 탐지:** 채용공고의 차별·주의 표현 탐지 방식 및 경고 정책 확정

검토 결과는 관련 PRD·TRD 및 기술 아키텍처 문서에 반영하여 문서 간 일관성을 유지할 예정입니다.

※ 본 문서는 **v1.5 초안 기준**이며, AI 모델 배치 방식, 동시 면접 처리 상한, OCR 정확도 및 성능 목표 등은 실제 운영 서버에서의 측정과 팀원 협의를 거쳐 최종 확정할 예정입니다.
